# PDF Compressor · 本地 PDF 压缩工具

使用链接:[https://muz777.github.io/PDF-/](https://muz777.github.io/PDF-Compressor/)

一个**纯本地、单文件、跨平台**的 PDF 压缩工具。借鉴 Adobe Photoshop「存储为 Web 所用格式」的**四联预览**思路，让你在压缩前直观比较不同质量的画质与体积，选定后一键压缩整个 PDF，自动把体积控制在目标大小以内（默认 ≤ 15 MB）。

🔒 所有处理都在浏览器本地完成，**零网络请求、零上传**，PDF 不会离开你的设备。

---

## 简介

传统 PDF 压缩工具大多只能给出一个质量滑杆，你无法判断「Quality 25」到底会糊多少、省多少。本项目的核心是：

> 把每一页 PDF 当作一张图，用 **Photoshop 四联预览**的方式，把「原图 / Q30 / Q25 / Q20」并排展示，让你亲眼看到画质损失与文件体积之间的权衡，再决定最终参数。

主要特性：

- **四联预览**：原图 + 三个 JPEG 质量档并排对比，显示尺寸 / 大小 / 体积减少百分比 / 预计最终 PDF 大小
- **同步缩放与拖动**：四个预览窗 100% / 200% / 400% / 800% 同步缩放、同步平移，可对比同一细节区域
- **自动目标体积**：默认 ≤ 15 MB，超目标自动逐级降档（Quality 30 → 28 → 25 → 22 → 20 → 18 → 15），在达标前提下尽量保持高画质
- **完全本地**：PDF 解析、渲染、压缩全部在本机浏览器内完成，无任何网络请求
- **单文件、免安装**：打包产物只有一个 `index.html`，双击即用，Windows / macOS / Linux 通用
- **绝不覆盖原文件**：输出固定为 `原名_压缩版.pdf`

## 用法

### 直接使用（无需安装）

1. 打开 `dist/index.html`（双击即可，或拖进任意浏览器窗口）
2. 拖入 PDF，等待分析
3. 进入四联预览，切换质量档、查看画质与预计体积
4. 点击「应用并压缩」，等待完成
5. 下载 `原名_压缩版.pdf`

> 也可以把 `dist/index.html` 单独发给别人，或部署到 GitHub Pages / 任意静态托管，一个文件就是完整应用。

### 开发 / 构建

```bash
npm install       # 安装依赖
npm run dev       # 启动开发服务器
npm run build     # 打包为单文件 dist/index.html
npm run smoke     # 运行冒烟测试
```

## 技术架构

| 层 | 技术 | 作用 |
|---|---|---|
| UI | React 18 + TypeScript | 四联预览、控制面板、进度/结果页 |
| 构建 | Vite 6 + `vite-plugin-singlefile` | 全部依赖内联成单个 HTML 文件 |
| PDF 渲染 | pdf.js（pdfjs-dist，Apache-2.0） | 本地解析 PDF、把每页渲染成位图 |
| PDF 重建 | pdf-lib（MIT） | 把压缩后的页面 JPEG 按原页面尺寸重组为新 PDF |
| 图片编码 | 浏览器原生 Canvas `toBlob('image/jpeg')` | JPEG 压缩（自动剥离元数据） |
| 解压 | pako（MIT） | Flate 数据解压（供分析用） |

### 核心处理流程

```
PDF 文件
   ↓  pdf.js 本地解析（页数、页面尺寸）
   ↓  逐页渲染成位图（白底）
   ↓  Canvas 编码为 JPEG（指定 Quality / 最大长边）
   ↓  pdf-lib 按原页面尺寸重建 PDF
   ↓  校验（页数、页面尺寸一致）
   ↓  若超过目标体积 → 自动降档重压
   ↓  下载「原名_压缩版.pdf」
```

### 模块划分（`src/engine/`）

```
pdfEngine.ts          PDF 加载 / 页面渲染 / 重建（pdf.js + pdf-lib）
imageEngine.ts        位图 → JPEG 编码、JPEG 解码回显
compressionEngine.ts  整页压缩管线（逐页渲染 → 压缩 → 重组）
sizeController.ts     目标体积自动控制与降档阶梯
previewEngine.ts      四联预览变体生成、预计体积估算
validator.ts          输出 PDF 校验
exporter.ts           命名规则与本地下载
```

## 设计思路

### 1. 四联预览（Photoshop 式对比）

单纯给一个 Quality 数值，用户无法判断字体是否发虚、人脸是否出色块、细节是否丢失。因此采用「原图 vs Q30 vs Q25 vs Q20」的并排预览，把「画质损失」和「文件体积」同时摆出来，让用户基于肉眼判断做决定——这也是本工具区别于普通压缩器的核心。

### 2. 整页栅格化（本项目的当前实现）

每页渲染成一整张位图再压缩，优点是**稳健**：不依赖 PDF 内部图片的编码细节（ICC 色彩配置、多重滤镜、CCITT/JBIG2 等），几乎能处理任意 PDF。代价是输出 PDF 的文字层会变成图片（不可搜索/复制）。

> 开发需求文档中还规划了更精细的「图片对象级」模式（只替换 PDF 内部图片、保留文字/矢量层），但实测发现真实世界 PDF 的图片编码非常复杂，对象级替换容易失败，故当前版本采用整页方案，优先保证可用性。

### 3. 完全本地、隐私优先

针对「学校 / 企业电脑无安装权限、受 MDM 管控」的场景，做成单文件网页版：不需要 Python、Node、管理员权限，打开即用；全程无 `fetch` / `XMLHttpRequest` 上传，代码审计可做到 **Network Request = 0**。

### 4. 自动降档的「少损失」策略

不是一上来就用极低质量，而是从较高质量开始尝试，逐级降低，在「≤ 目标体积」的约束下尽可能保住画质。

## 已知限制

- 输出 PDF 为**整页图片**，文字不可搜索、不可复制
- JPEG 为浏览器 Canvas 产出的**基线编码**，「渐进式 / 优化」为近似效果
- 极旧浏览器（如很老版本的 Safari）可能无法运行，需要 ES2022 支持
- 目标体积为「尽力逼近」，极端内容下可能无法降到目标值
